# TradeLab — cTrader Range candle integrity and latency verification

## Confirmed code faults addressed

1. **Invented bodies in visual projection.** The old `RangePhantomBars` split one genuine wide OHLC candle into many translucent bodies at identical timestamps. The chart could look discontinuous despite the actual broker history remaining untouched. Real candles are now never replaced. Optional visual bars can fill only *between* distinct real bars; existing installations migrate to real-only mode once.
2. **Cancellable loading.** Android's former synchronous `OkHttpCall.execute()` could keep running after a Range, symbol, account, or date change, holding the tick-window mutex. HTTP now uses cancellation-aware callbacks and cancels the underlying call when the coroutine is cancelled.
3. **Broker payload truncation.** A successful Tick JSON body larger than two million characters was previously rejected as a generic I/O failure. Tick bodies have a separate, bounded eight-million-character ceiling; exceeding it is explicitly classified as dense history so the existing *real-data-only* slicer can split the period and retry.
4. **First paint blocked by all history pages.** The newest real quote slice is requested first, then the remaining pages. A visible preview is explicitly marked provisional; indicators are suppressed until the whole selected window completes. The final quote sequence is still chronological.
5. **Fixed-size inefficient requests.** The first request covers the newest hour; following batch lengths (one to six hours) depend on the number of real quotes returned per hour. Exact-hour boundaries no longer issue another HTTP call for just one millisecond. Dense requests split newest-first.
6. **Read-only transient network errors.** Only HTTP 429/500/502/503/504 are retried, at most twice per slice, with bounded delays. Authentication errors, malformed market prices, and other permanent failures stop immediately.
7. **No on-device evidence for suspicious bars.** The Range settings show genuine Bid quote count, same-millisecond quote count, quote jumps larger than the configured Range, largest observed jump, oversized real candles, and measured first-page/full-load elapsed milliseconds.
8. **Misleading active timeframe.** The bottom chart strip shows the selected Range size when Range style is active; tapping it opens Range settings rather than an unrelated minutes menu.
9. **Broker-specific symbol display precision was never requested.** The light cTrader symbol list does not include price digits. A new authenticated, read-only `/v1/symbol-detail` uses `ProtoOASymbolByIdReq` (2116) and reports broker `digits` and `pipPosition`. Android caches the account-specific response and checks whether the configured local price step is even representable at broker precision; it does **not** claim that `digits` alone establishes the broker's actual minimum price change. A 404 from an older deployment is explicitly flagged, with a 60-second negative cache to avoid repeating the request on every chart action.
10. **Silent price-step rounding.** The Range engine previously rounded a quote to the nearest local tick even if the genuine price was in between. It now rejects an incompatible price step with an explicit Arabic diagnostic. This prevents charts that look aligned but were calculated from modified broker prices; the local configuration still must be checked against the actual broker tick size.
11. **Repeated heavy reconstruction.** A bounded, two-entry memo reuses verified results for exactly the same broker quote-list identity, symbol, source, price step, Range size and incomplete-bar mode. Sliding to a different historical window or switching accounts invalidates the old results; no cached future prices enter Replay.
12. **Jumping chart while prefetching.** When an older Range window is requested for the same visible end time, the chart retains its previous complete snapshot until the new one is fully calculated; provisional preview is still available on a cold chart. The viewport restoration now searches for the original quote time *inside* a regrouped candle's time span and disambiguates overlaps by price, instead of relying only on an unstable opening timestamp.
13. **Old hollow-candle preference leaking into Range.** Verified Range bodies always render solid red/green by default; only explicitly marked visual-only gap markers may be outlined. The former chart-wide `hollow up` preference no longer makes genuine bullish Range bodies look empty.
14. **No visible loading breakdown.** The chart tracks genuine quotes and completed broker batch slices as they arrive. The Range settings expose slice/quote counts alongside first-paint and full-load durations to help separate slow broker downloads from expensive Android reconstruction.
15. **Large historical JSON payloads over mobile data.** The `/v1/ticks` response now supports asynchronous, low-CPU gzip when the Android HTTP client advertises compression and the page exceeds 64 KiB. Small pages remain uncompressed, `Vary: Accept-Encoding` is included, and `no-store` remains enforced. This is transport compression only: the price and timestamp objects round-trip unchanged. Actual mobile latency improvement depends on the broker response and network and has not yet been benchmarked on a device.
16. **Cancelled download restarted from the first quote page.** A bounded `RangeTickSuffixCache` now retains only the latest contiguous, fully validated cTrader BID quote pages (including genuinely empty periods), keyed by the account/source and exact chart cutoff. On retry it requests only the missing earlier interval and appends the saved suffix without overlapping timestamps. A separate 200,000-quote limit trims oldest completed slices to avoid unlimited phone memory growth. A changed symbol/account/end timestamp never reuses the previous suffix.
17. **Avoidable large list allocations while extending Range history.** When a new requested window fully contains the existing verified tick window, the merged list already has exactly the requested limits and need not be filtered/copied. An explicit size check now runs before allocating an oversized merged list, so dense gold histories fail safely rather than briefly allocating beyond the configured one-million-quote cap.
18. **Verified data loss at the broker's truncated-page boundary.** The earlier Android implementation advanced the next page to `oldestTimestamp - 1 ms` when cTrader returned `hasMore=true`. Multiple genuine quotes can share that millisecond, so this cursor silently discarded older quotes with the same timestamp. The official cTrader Open API documentation explicitly says `hasMore` means the tick response was truncated. Both gateway and Android now treat this as an incomplete interval, never as usable candle input. The downloader recursively splits into disjoint, contiguous millisecond intervals and merges complete leaves chronologically. If even a one-millisecond interval is truncated, it fails explicitly rather than inventing an order or missing prices. Source: https://help.ctrader.com/open-api/symbol-data/
19. **Dense split progress could not survive cancellation.** Verified callback notifications formerly occurred only after the original whole hour finished, even when many smaller pages had completed successfully. Each complete bisection leaf is now saved newest-first immediately. Restarting a cancelled load reuses only the exact contiguous, source-account-bound suffix; it does not re-fetch the already verified quote timestamps. A nested split cancellation/resume regression test checks this behavior, including same-millisecond quotes.
20. **Large quote-page parsing and merging could block chart gestures.** The chart's `LaunchedEffect` previously invoked the tick loader on Main. Although OkHttp transport was asynchronous, validation and multi-page list merging executed on Main between requests. The full range load now runs on `Dispatchers.Default`; only small Compose progress/snapshot mutations return to `Dispatchers.Main.immediate`. Actual frame-time improvements have not been measured on an Android device.
21. **Dense requests hid progress and could grow unbounded before the cap.** Quote counts and UI updates previously advanced only when the original full hourly page finished, not as individual complete sub-pages arrived. Each verified leaf now increments the actual downloaded-quote and completed-page counters. The one-million-quote window cap is checked before a split parent combines its child lists. These are counting and memory-safety improvements, not estimated speed benchmarks.
22. **Repeated costly 1-hour dense subdivisions.** After loading a busy full hour, the next request was still at least one hour, forcing the broker to reject and split repeatedly. The next interval now uses the real number of verified BID ticks in the completed period to target about 50,000 ticks, bounded from one minute to six hours. Every interval is still continuous, disjoint and broker-complete; the measured density is used only to size the *request*, never to generate prices. The dense-window tests lock down the requested millisecond span and full sequence.
23. **Unnecessary nested list copies in overflow handling.** Recursive subdivisions previously concatenated `oldest + newest` on every level, copying quote references O(n × depth) before a separate chronological flatten. Complete leaf pages now append to one newest-first list and undergo a single final chronological copy. Exact quote order (including same-millisecond changes) and gap-free interval coverage have new regression assertions.
24. **Cancelled older-history extensions restarted their already finished downloads.** The verified suffix cache had applied only to cold chart loads; an interrupted *pan into older history* bypassed it. `RangeTickWindowContinuation` now reuses an exact contiguous broker/source-bound suffix when extending a complete window. Tests cancel both ordinary and nested dense older downloads and compare the resumed output against the original fixture.
25. **Quoted history excluded from a new Replay window still consumed memory.** When the request narrowed or shifted, the old code initially merged the entire cached quote list and then linearly filtered up to a million prices. A binary-search inclusive window slice now keeps just the needed quotes, including every price within duplicate millisecond boundaries. Download budgets account for already retained quotes *before* fetching/allocating new pages. No unrevealed future quotes can be reused in a narrower Replay window.
26. **Insufficient reproducible field diagnostics.** Range settings now include a minimum-48dp, user-triggered “نسخ تقرير فحص شموع المدى” control. It copies the symbol, selected Range, chart cutoff, completeness, real Bid quote and page counts, duplicate timestamps, oversized/jump counts, measured load durations, and any error. It deliberately omits access tokens and brokerage account IDs. This enables comparison of the exact problem window without guessing from screenshots alone.
27. **Build workflow ignored the actual Range fix branch.** The Android APK workflow now covers `fix/ctrader-range-*` and `feat/ctrader-range-*` branches, not just the single original dated branch. CI still must run before an APK from this work can be called verified.

## Truth and trading integrity boundaries

- The **only** metals/forex source remains the signed-in user's cTrader **historical BID quotes**; crypto continues to use the existing Binance source.
- The Range algorithm retains each observed quote and never guesses missing prices; individual bars may legitimately exceed the requested range if the next observed quote jumps farther than that range.
- Visual-only, incomplete, or provisional values must not enter replay trading, backtesting, statistics, or real-time indicator calculations.
- `hasMore` no longer uses cursor-based pagination. The only accepted intervals are complete `hasMore=false` responses, with bisected disjoint intervals for dense market periods. No quote may be discarded based on its shared millisecond timestamp. A live authorized cTrader session is still needed to validate real broker histories and bar-by-bar parity.
- Range regrouping can change when the earliest tick of the selected historical window changes. Exact session-anchored parity with another chart application is **not proven** by the current code; proving that requires a broker tick fixture and a clearly specified anchoring/session rule.
- Broker display `digits` and `pipPosition` cannot, alone, establish `TickSize`. The gateway and Android now expose and validate known facts instead of guessing a source-independent broker-specific step. The metadata endpoint needs to be deployed before its verification can run on devices.

## On-device acceptance checklist (requires actual rebuilt APK)

1. Open `XAUUSD → مدى 100`. Verify the status shows genuine candles by default, zero optional Phantom bars, a correctly labeled `مدى 100` interval, and the real Bid quote count.
2. Pan backwards while keeping the chart visible. The latest genuine prices must appear before an older backfill finishes; the transient indicator should say the initial candles are provisional until completion.
3. Use `مدى 1000` and repeat the backfill; compare measured first-page and full-load milliseconds with the previous APK on the same cTrader account, window, and network. Never claim a speedup without those measurements.
4. Switch Range sizes or symbols while the spinner is active. The abandoned request must cancel; its old candles must not overwrite the new symbol/size.
5. Inspect any oversized candle: check its exact OHLC, the reported real-quote jump count, and if necessary a broker Tick fixture. Never smooth it with fake trade prices.
6. Run Replay at a fixed historical cutoff. There must be no future quote or virtual bar used in trade execution/results.
7. Check older-history boundaries and multi-quote timestamps against raw cTrader BID data for any remaining discontinuity.
