## Policy
Dependency-aware warm-up, max of ACTIVE indicator requirements including [n] lags, per source/timeframe. Default example: 36 confirmed previous bars so both previous/current HA have reached <1e-8 in this capture, before first allowed signal; 36 is an empirical lower recommendation, not universal. [1] matters for model/stop. HA differences relative to external TradingView source may exceed 1e-8 outside original exclusion (e.g. row 5291 1.42595e-8); separate source mismatch from seed convergence. Numeric tolerance does not imply exact strong predicate equality; require stable decision margins or mark uncertainty near threshold/direction/price comparisons. Where a previous trusted HA state is available use it. For arbitrary restart, without known initial error bounds no universal guarantee. No future rows used to determine readiness. Use conservative historical seed bound or compare causal prefix computations with successively longer earlier prefixes. If insufficient history warn, suppress automatic signals in strict mode and allow chart inspection. Recompute only when input flags/pack/timeframe/length change or earlier history changes. Examples: useTrend or trendGate EMA => EMA200; align or gate 'ترتيب EMA' => EMA20/50/200 and EMA50[slopeBars]; strongPack => align, prior, DI/ADX, close/body; useExt => EMA50/ATR14; kFvg => ATR[1] + FVG state; useVol => ATR; useMacd => MACD signal; useHtf or HTF/All gate => confirmed HTF HA history in HTF bars; useSt or ST/All gate => ST; SMC needs pivots and event histories, not merely fixed length. Prior rolling indicators with lag and structure may need more actual events. Unknown dependency => conservatively require history, not silently ignore. Earlier counts for EMA/RSI/ATR etc are empirical from prior reference analysis, not universal bounds. Separate indicator readiness from strategy state: trendAge, armed/zone, position/closedtrades and persistent variables cannot generally be reconstructed by finite numeric warm-up. Exact full-history parity requires same start or verified causal checkpoint including all state/orders; training from flat at replay start is a separate explicitly labeled mode. Never leak future or recreate earlier orders from future knowledge; use confirmed HTF only. No implementation.
