# General interpreter scalar stage A — candidate
Not special-cased for the strategy. The legacy numeric engine is unchanged. Candidate AST dispatch math.floor/sign/sum, str.contains, bounded decimal str.tostring, explicit UTC/fixed-offset str.format_time, typed Pine RGBA and color.new. Uses documented scalar subset; general string/format/color registry stays partial until additional evidence (especially mintick, IANA, rounding, na). math.floor/sign/sum are proposed registry promotions in this unmerged PR, gated by real Pine source execution and exact CI; do not merge unless tests pass. String/color tests use real V2 OHLC, but oracle values are independent formulas, not TradingView-exported columns. No TradingView parity claim. Stateful sums bound by call path and history, repeated same written call in one bar explicitly rejected. Tests check full 5334 rows, mask and warmup, replay 3000/1000/3000 poisoned future, existing differential and diagnostic census. Future stages: tuple, arbitrary history, metadata, Pine strategy and rendering remain unimplemented. Sources https://www.tradingview.com/pine-script-reference/v6/ and https://www.tradingview.com/pine-script-docs/concepts/strings/ and https://www.tradingview.com/pine-script-docs/visuals/colors/. No original fixture changes.
